  <name>Task 1: Create useProctoring hook</name>
  <files>src/hooks/useProctoring.js</files>
  <action>
Create src/hooks/useProctoring.js as a named export following the hook conventions: one concern, returns an object of state + actions, useRef for mutable refs, useCallback for actions, useEffect for event-listener lifecycle mirroring useTimer.js.

The hook signature: export function useProctoring({ active = false } = {}).

Internal state: violations (number, useState(0)), switchedAway (boolean, useState(false)).

Event listeners: attach both 'visibilitychange' on document and 'blur' on window when active is true, remove them on cleanup (return cleanup fn from useEffect). Guard against double-fires by using a ref flag (lastHiddenRef = useRef(false)) — set it true on the first of the two events in a single "away" event, reset it false when the player returns (visibilitychange back to 'visible', or window 'focus'). Increment violations by 1 per discrete departure, not per event. The return-to-visible/focus events themselves must never increment violations.

Handlers: visibilitychange fires when document.visibilityState === 'hidden' AND lastHiddenRef.current is false → set lastHiddenRef.current = true, setViolations(v => v + 1), setSwitchedAway(true). On visibilityState === 'visible' → reset lastHiddenRef.current = false, setSwitchedAway(false). window 'blur' → if lastHiddenRef.current is false → same increment + setSwitchedAway(true). window 'focus' → reset lastHiddenRef.current = false, setSwitchedAway(false).

useEffect depends on [active]. When active becomes false, remove all listeners and setSwitchedAway(false) (do not reset violations — consumers need the running total).

reset action (useCallback): setViolations(0), setSwitchedAway(false), lastHiddenRef.current = false.

Return: { violations, switchedAway, reset }.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser DOM events → hook | visibilitychange and blur are browser-native; attacker cannot spoof them to inflate counts, only suppress them (irrelevant — suppression helps the attacker, not the reviewer) |
| Client → GAS POST | proctoring_violations is a self-reported integer; a motivated candidate can send 0 in the payload |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5to-01 | Tampering | proctoring_violations in POST payload | accept | Count is advisory evidence for human reviewer, not an automated gate; falsification risk is low-stakes and expected (stated in spec: "detect and flag only") |
| T-5to-02 | Denial of Service | Double-fire of visibilitychange + blur on same hide event | mitigate | lastHiddenRef guard prevents double-increment; one departure = one violation |
| T-5to-03 | Information Disclosure | sessionStorage SOC submission now includes violation count | accept | sessionStorage is same-origin only; count is non-sensitive scoring metadata |
</threat_model>
